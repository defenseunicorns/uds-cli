## What you'll accomplish

Package disassembly recovers the assets and `zarf.yaml` from a complete Zarf package. The command writes packaged charts, manifests, files, images, and repositories to local paths and rewrites `zarf.yaml` to use them.

Disassembly supports rapid development and debugging when a fix must be tested against a created package, especially in a disconnected environment. The recovered tree is a temporary working copy rather than a new source of truth. Keeping fixes only in that tree separates them from upstream and leaves future packages without potentially critical fixes and makes debugging more difficult across environments. Lasting fixes therefore belong in the original upstream source, with final packages published from that canonical source. This temporary role is why the command lives under `dev`.

By the end of this guide, you'll have temporary source that can rebuild the package without pulling its declared resources from remote sources.

> [!CAUTION]
> Disassembly and rebuilding change the package, so its original signature no longer applies. Environments that require signed packages need a new signature and corresponding verification material for the rebuilt artifact.

## Prerequisites

- [UDS CLI installed](/getting-started/installation/)
- A valid local or remote Zarf package source
- Registry or network access when the source is remote

## Steps

<Steps>

1. **Choose the package source and output directory**

   This example uses a local package and writes source to `./app-source`. The output directory must either not exist or be empty.

2. **Disassemble the package**

   <Tabs>
     <TabItem label="Legacy">

       ```bash
       uds dev disassemble \
         zarf-package-app-amd64-1.0.0.tar.zst \
         ./app-source
       ```

       Legacy mode reports successful completion as human-readable CLI output.

     </TabItem>
     <TabItem label="Next">

       ```bash
       uds --features=NextMode=true bundle dev disassemble \
         zarf-package-app-amd64-1.0.0.tar.zst \
         ./app-source
       ```

       Next mode writes text by default and supports `--output json` or `--output yaml` for structured output.

     </TabItem>
   </Tabs>

3. **Review the generated source**

   The generated `app-source/zarf.yaml` references assets beneath `app-source`, and the package version ends in `-disassembled`.

   > [!CAUTION]
   > Removing the automatically added `-disassembled` suffix makes offline debugging and support harder because a locally rebuilt package can be mistaken for the unchanged upstream artifact. The suffix preserves that modification context in the package version which is easy to see in views that list installed packages across Zarf and UDS.

4. **Rebuild the package offline**

   ```bash
   uds zarf package create ./app-source --confirm --output ./build
   ```

   The rebuild uses the local assets emitted under `app-source` and does not pull images or other declared package resources from remote sources.

</Steps>

## Verification

A package archive beneath `./build` confirms that the generated source is buildable. It does not confirm deployment behavior; the rebuilt artifact still needs validation against its intended environment.

## Troubleshooting

### Problem: The output directory contains files

**Symptom:** Disassembly reports that the output directory must be empty.

**Solution:** Choose a directory that does not exist or remove its contents before running the command.

### Problem: The package is differential or skeleton

**Symptom:** Disassembly reports that the package does not contain complete recreatable source.

**Solution:** A differential package is created from a previously created package and new source and contains only the pieces that changed. It cannot reconstruct complete source by itself; recovery requires both the complete created package and the source used to produce the differential.

A skeleton package is a published, uncreated package intended for reuse and composition across package repositories. It already represents reusable source input and has no created package assets to recover through disassembly.

### Problem: A repository-bearing output directory was moved

**Symptom:** Rebuilding fails to locate a repository after the generated source directory was moved.

**Solution:** Moving the generated source breaks its absolute `file://` repository URL. Rebuilding succeeds again when the directory is returned to its original location.

Zarf currently uses one repository URL for both source acquisition and repository identity. The rebuilt package remains portable because Zarf rewrites that URL for its in-cluster Git service during deployment. Repeated disassembly and rebuild cycles from different absolute paths are not path-idempotent however because Zarf derives the packaged repository suffix from the URL.

### Problem: The source is a UDS Bundle

**Symptom:** Disassembly cannot load the source as a Zarf package.

**Solution:** Select a complete Zarf package. Bundle disassembly is not supported.
